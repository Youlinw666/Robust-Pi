# VLA算法实习：最终简历与面试版本

项目名称：**Robust-Pi：低资源π₀适配、闭环评测与失败诊断**。

## 三条精简简历描述

1. 基于固定openpi/LIBERO搭建π₀适配管线，完成五任务各40-shot数据准备、train-only统计、100-step LoRA pilot及checkpoint fresh reload，运行于12GB显存/20GB内存约束。
2. 实现身份校验与资源守门，复用2条Clean、串行完成2条Visual OOD闭环；保存动作/视频/资源证据，任务结果如实为0/2与0/2，无系统错误。
3. 用轻量CPU审计动作变换与训练统计，定位训练/推理图像方向相差180°，形成版本化修复设计、证据边界和可复现负结果分析。

证据见[实际结果](../reports/EXPERIMENTS.md)、[失败分析](../reports/FAILURE_ANALYSIS.md)。不要添加“鲁棒性提升”“充分收敛”“仅训练adapter”“20个adapter叶都已更新”“完整benchmark”或“真机部署”。

## 约两分钟项目介绍

我做的是一个资源受限的VLA工程项目，用RTX5070十二GB显存、WSL二十GB内存，把数据、π₀微调、checkpoint验证和LIBERO闭环评测连起来，并保存可核对的证据。

数据采用五任务episode级划分，每任务四十条训练示范，统计只使用对应训练池。模型来自固定openpi，视觉和语言形成prefix，动作expert通过attention读取条件，由Flow Matching生成连续动作块。E1只做百步、batch一的LoRA pilot，保存params与normalization assets，做了fresh reload和冻结叶检查。实际还有视觉/投影参数可训练，不是仅adapter更新。

评测时，我复用两条旧Clean，预登记两条新视觉扰动case，固定task/init、模型、stats、随机源和H50/K5，第一条通过系统与资源验收才启动第二条。四条都跑满二百二十步，无系统错误，但任务成功都是零。链路跑通和模型能力我分开汇报，没有混入官方E0成绩。

随后我用CPU核对动作、归一化和控制器，数值链路复核通过，却发现formal训练图像保持raw方向、rollout旋转一百八十度。这一缺陷由代码与真实像素审计证实，但尚无修复后对照，不能说它解释全部失败。百步仍在warmup，也不能当充分收敛。

项目最终贡献是训练工程、受控评测、资源管理与静态缺陷定位；负结果和修复未验证状态都明确披露。公开候选只保留可审阅代码与脱敏摘要，排除了模型、数据、媒体和私密日志。

## 五个最可能被追问的问题

**1. 为什么训练完成后成功率仍为0？** 完成的是100步预算和产物验收，不是收敛。确认了视觉预处理合同不一致；动作往返及统计核对通过。100步仍在1000步warmup，且只有两个Clean case。先定位可证实缺陷，再做版本化CPU回归，不能直接归咎于训练不足，也不盲目加训。

**2. 如何清楚解释180°问题？修好了吗？** 同一raw HDF5帧与formal Parquet逐像素相等，证明训练输入未旋转；rollout源码明确双轴反转，方向相差180°。这是表示约定不一致，不是机器人world state/action坐标需要旋转。只完成修复设计，没改旧数据/checkpoint，更没有修复后的任务成功率。

**3. π₀、Flow Matching、H50/K5有什么关系？** 图像/语言prefix与state/带噪动作suffix通过多分支attention连接。模型学速度场，推理默认10步Euler从噪声走到动作块；H50是预测长度，K5是只执行前5步后重新观察，两者不等于积分步数。

**4. LoRA到底训练了哪些参数，证据够不够？** 两个Gemma分支用rank16/32 LoRA，冻结过滤器没有冻结所有视觉/投影参数。17个冻结base叶匹配、33个可训练非LoRA base叶有变化；20个LoRA叶非零不证明相对初始化更新，因为本实现A/B随机初始化。缺少初始化adapter差值就不夸大更新量。

**5. 如何在5070+20GB下管理资源并比较鲁棒性？** 区分host RAM与VRAM，使用逐leaf BF16 restore、params+assets保存、单模型串行和JAX配置；监测MemAvailable/GPU free/swap/进程组，危险即停止。Clean0/2使retention分母为0，应为N/A；两对只做描述，不声称完整benchmark或提升。

## 投递时的边界

可用来展示VLA数据与模型工程、评测、调试和诚实的算法诊断；不能用它证明已训练出高成功率策略。建议开始投递，停止盲目追加GPU训练；CPU修复设计可并行准备。任务能力相关岗位追问时，应主动说明当前负结果、小预算和未完成的修复验证。
